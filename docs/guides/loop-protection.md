# 环路与 STP

页面：**系统功能 → 环路与STP**（`/loop_stp.html?nav=1-7`）。

两个标签页：**环路检测**、**STP**。本次只读了选项和当时显示，没有制造环路，也没有抓 BPDU。

|---|---|

| 时间间隔 | 10 × 0.1 秒 = 按标注为 1 秒 |

| 每端口 STP 状态 | 全部「转发」 |

## 环路检测

字段：

- 环路预防：总开关
- 时间间隔：0 或 1–100，单位 **0.1 秒**
- 恢复时间：0 或 1–100，单位 **秒**
- 逐端口状态列：当时读到的单元格为空，不能用来判断端口是否已因环路被阻断

数值 0 的含义页面没写。不要把它解释成禁用、立即恢复或永远不恢复。

「禁用全部」按钮的范围未验证：是关环路检测、关 STP，还是两个都关。

## STP / RSTP

页面只提供：

- STP 与 RSTP 二选一
- 每端口「边缘端口」复选框（带表头全选）
- 每端口状态

没有桥优先级、端口路径开销、Hello、Max Age、Forward Delay，也没有根桥 / 指定桥 / 指定口这类细节。

因此：

- 不能从「选中 RSTP」推出它已经按 802.1w 完整运行
- 不能描述它和环路检测谁优先、会不会同时动作
- 家庭场景如果只有一台交换机、没有故意做环，RSTP 选中且口都在「转发」，并不能说明防环已经有效

## 使用建议（保守）

- 拓扑里可能出现环（两台交换机双线、MESH 口误连）时，至少不要把两个功能都关掉。
- 接电脑、NAS 的口可以考虑勾边缘端口，但这是否等价于 PortFast、会不会再等转发延迟，未验证。
- 接另一台交换机或 AP 有线回程的口不要随手勾边缘端口。
- 改完后看状态列是否仍全是「转发」；若出现其它中文状态，请带到 Issue 里（连同固件版本）。

制造环路来测试会中断网络。不要在生产环境为了给本仓库填坑而故意环上。
