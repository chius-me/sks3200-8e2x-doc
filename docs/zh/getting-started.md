# 第一次登录

## 出厂管理入口

下面两项**没有**在本次 2.0.0.1 核对中直接读到（该机管理地址和账号都已被改过）。
[厂商手册 V2.0](reference/vendor-manual.md) 和多篇独立评测一致，因此作为出厂值写下：

| 项 | 值 |
|---|---|
| 地址 | `http://192.168.10.12` |
| 用户名 | `admin` |
| 密码 | `admin` |

V2.0 手册要求第一次登录后改掉默认密码。本次核对走的是 HTTP，未见强制 HTTPS。

## 电脑怎么连

1. 用网线把电脑接到任意 RJ45 口（不要指望 Console 口上 Web）。厂商手册 V2.0：电脑必须接到交换机的以太网口上。
2. 把电脑 IPv4 设成 `192.168.10.x`，**x 为 2–254**，掩码 `255.255.255.0`。**不要**用 `192.168.10.12`。例如 `192.168.10.10/24`。网关可以先空着。
3. 浏览器打开 `http://192.168.10.12`。
4. 语言可选简体中文、English、Русский язык、日本語、한국어。正文按简体中文界面截字段名；英文菜单名跟厂商手册 V2.0。

若家里已经是 `192.168.10.0/24` 且 `.12` 被占用，先不要把交换机直接插进现网。用一根网线单独连电脑，改完管理地址再接入。

## 登录后先做的三件事

### 1. 改密码

**系统功能 → 用户**

表单是「新用户名 / 当前密码 / 新密码 / 确认新密码」。
可见页面没有用户列表、多账号或角色。密码长度和复杂度规则页面也没写。

### 2. 改管理地址

**系统功能 → IPv4地址**

| 配置项 | 可选值 |
|---|---|
| DHCP 设置（IPv4） | 禁用、启用 |
| IP 地址 | IPv4 |
| 子网掩码 | IPv4 掩码 |
| 默认网关 | IPv4 |

这是交换机自己的管理地址，不是 DHCP 服务器，也不是 VLAN 间路由。
页面**没有**管理 VLAN ID。厂商对 SKS32 系列的说明写过：无论端口属于哪个 VLAN，都可用新 IP 访问管理界面——那是厂商说法，本仓库未在 2.0.0.1 上验证。

改完 IP 后，浏览器要换成新地址才能再登录。电脑也要回到新网段（或重新走 DHCP）。

### 3. 点「保存」

多数页面同时有「应用」和「保存」。厂商手册 V2.0 把 **Apply** 写成应用新设置，把 **Save** 写成保存当前配置。手册没有写重启或断电后的行为。

本次**没有**用重启验证持久化。保守做法：改完先「应用」，再点一次「保存」，然后按你自己的维护窗口重启核对。
详见 [公共按钮](webui/index.md#公共按钮)。

## 找不到页面时

- 电脑和交换机不在同一网段。
- 交换机已经被前人改过 IP。用路由器客户端列表、`arp -a` 或断网单连后再扫网段。
- 账号不是 `admin`。面板上的 RST 孔在公开资料里用于恢复出厂；长按时间因文案而异。**本次没有按过 RST**，因此不把具体秒数写成已验证步骤。恢复范围（是否保留管理 IP）也未验证。

## 不要在第一次登录时做的事

- 不要在生产链路上直接改 VLAN 成员，除非你能接受管理口暂时失联。
- 不要上传来路不明的固件。
- 不要把「恢复」理解成一定保留管理地址。页面没有解释恢复范围。
