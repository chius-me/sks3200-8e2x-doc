# 链路聚合

页面：**高级设置 → 链路聚合**（`/link_aggregation.html?nav=2-4`）。

字段名和范围来自 2.0.0.1 中文界面。静态 / LAG / LACP、Priority、超时秒数来自 [厂商手册 V2.0](../reference/vendor-manual.md)。本机没有真正建过聚合组，也没有抓过 LACP。

## 页面上实际有什么

每个端口一行，外加一个全局「LACP系统优先级」（当时显示 32768）。

| 中文界面 | V2.0 英文 | 选项或范围 | 静态模式下 |
|---|---|---|---|
| 端口类型（第一列） | Port Type | 静态、LAG、LACP | 当时全部为静态 |
| 端口类型（1–65535） | Priority | 聚合协议用的端口优先级 | 128，输入框禁用 |
| LACP超时时间 | LACP Timeout | 短 = **3 秒**，长 = **90 秒**（厂商） | 短，控件禁用 |
| 聚合组 | Aggregation Group | 0–15；厂商：最多 **16** 组 | 0，输入框禁用 |
| LAG状态 | LAG Status | 只读 | 随链路亮/灭 |

两个字段都叫「端口类型」是中文界面原文。V2.0 把数值列叫做 **Priority**。

厂商要求：成员口的速率、双工、VLAN 应一致。

页面上没看到：

- 散列算法（源 MAC / 目的 MAC / IP / 端口）
- LACP 主动 / 被动
- 对端系统 ID、对端口、聚合是否同步
- 把聚合口当成一个逻辑口再去选 VLAN 的单独对象

VLAN 仍按物理口 1–10 来选成员。聚合和 VLAN 的先后顺序、聚合口是否继承成员关系，都未验证。

## 三种模式（厂商）

| 页面选项 | 厂商手册 V2.0 | 这里仍未实测 |
|---|---|---|
| 静态 | 默认无聚合 | — |
| LAG | 静态链路聚合（手册里也叫 Eth-Trunk） | 本机真正建成静态聚合 |
| LACP | 用 LACP 的动态聚合 | 主动/被动、PDU、几条成员才转发 |

当时组号全是禁用的 0，不是已经在工作的聚合。

## 建议的操作顺序（未跑通）

在 NAS、路由器或对端交换机已经准备好对应聚合的前提下：

1. 下载配置备份。
2. 确认这些口没有在做镜像目的口，也尽量先理清 VLAN 成员。镜像、STP 边缘口与聚合的互斥未验证。
3. 只把**同一规格**的口放进一组：厂商要求速率、双工、VLAN 一致。不要把 2.5G 电口和 10G 光口混在一组，除非你接受被最慢那条拖住。
4. 将对端也设为同一模式（两边都 LAG，或两边都 LACP）。
5. 在本机把 Port Type 改成 LAG 或 LACP，填同一个非 0 聚合组，再应用、保存。
6. 看 LAG状态、对端状态，以及业务是否还在。有条件就看 LACP PDU。

若管理口就在即将加入聚合的物理口上，先保证另有一条能登录 Web 的路径。

## 和旧工具的关系

GitHub 上有针对 SKS3200-8E2X 的 `swctl` 一类脚本，其 VLAN 模型是「每个端口一组 VLAN + native + 创建 bridge」。
那是给**旧固件**用的。2.0.0.1 没有 Bridge ID 可填，不要把脚本输出直接灌进这一版 Web。
