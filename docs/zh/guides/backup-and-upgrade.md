## 备份

配置页提供「下载配置」。在改 VLAN、聚合或管理 IP 之前下载一份，是目前界面里唯一看得见的备份手段。

未知：

- 文件扩展名和能否用文本编辑器打开
- 是否包含密码、用户名
- 是运行配置还是启动配置
- 没点「保存」的内容会不会出现在导出里

导出文件按含有凭据来对待：本地保存，不要提交到 Git。

## 恢复配置

同一页有「选择文件」和「上传配置」。导入是否要求重启、是否校验型号、失败会不会变砖，都未知。

面板 RST 和页面上的「恢复」不是同一个已验证操作。页面「恢复」的范围未知；RST 长按秒数本次未测。

## 固件

固件页同样有下载和上传。

「下载固件」更像是从设备倒出当前镜像，不是检查官网更新。倒出的文件能否再刷回去、有没有校验和，未知。

上传固件时：

- 只使用与 **SKS3200-8E2X** 以及你的硬件版本匹配的文件
- 不要刷 5E2X、8E2X-P 或其它系列的包，除非你有独立、可重复的成功记录并愿意承担变砖
- 升级过程中保持供电
- 升级后是否保留 VLAN / 管理 IP，未验证——升级前仍应先下载配置

厂商固件请走厂商渠道。本仓库不托管固件二进制。

## 保存、重启、断电

若你接受厂商和社区对「保存」的通常解释：改完配置后点保存，再在维护窗口重启一次，确认 VLAN 和管理 IP 还在。

这是建议的验证方法，不是已经在 2.0.0.1 上做过的实验。欢迎把重启前后对照开成 Issue。
